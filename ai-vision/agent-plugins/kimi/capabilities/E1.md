# E1 Git 仓库信息识别

- **评分**: ❌
- **结论**: Kimi 的 hook 数据源已经提供可信 `cwd`，但当前实现没有采集 Git remote、HEAD branch 或 revision，也没有把 `vcs.*` 写入 Resource；这是数据源存在而实现缺失的工程缺口。
- **代码证据**:
  - `kimi/kimihooks/src/common/hook.rs:91` — `extract_cwd` 从每个公共 hook payload 读取 `cwd`。
  - `kimi/kimihooks/src/hooks/stop.rs:108` — Stop handler 使用 session/cwd 定位 host `wire.jsonl`，证明 cwd 可作为会话上下文来源。
  - `kimi/kimihooks/src/common/mod.rs:1` — common modules 中没有 Git/VCS collector；现有 `otel` 构造路径也未发现 `vcs.repository.url.full` / `vcs.ref.head.name` 写入。
- **Replay/source 证据**:
  - `kimi/kimihooks/tests/replay_fixtures.rs:51` — replay 固定从 wire fixture 重建 records，并把 cwd 固定为 `/tmp/test`；当前输出没有由该 cwd 派生的 VCS Resource 属性。
  - `kimi/kimihooks/src/common/otel.rs:2110` — 当前只把有效 cwd 写为 `agentic.runtime.cwd`，未继续探测 Git 或写 `vcs.*`。
- **缺失原因**: 数据源层有 cwd，但没有 Git probe、session-scoped VCS state 或 Resource 注入实现。补法是在生产/replay 共享语义边界内增加有界 Git collector，并让 replay 消费显式记录的 VCS source；不可用目录、超时和无 remote 必须 fail-open。
