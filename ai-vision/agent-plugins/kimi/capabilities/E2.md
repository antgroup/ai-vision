# E2 上游调用 TRACEPARENT 串联

- **评分**: ⚪
- **结论**: Kimi CLI/wire 数据源没有 W3C `TRACEPARENT`、上游 parent span 或等价的 host trace context；Kimi 代码也未消费该输入。当前每个 Turn 的 trace 是采集器在 replay/Stop 构造阶段生成的本地 identity，不能反推上游调用串联。
- **代码证据**:
  - `kimi/kimihooks/src/common/hook.rs:1` — Kimi hook 基础模块只定义公共 hook payload 与 session/cwd 提取，没有 W3C propagation 处理。
  - `kimi/kimihooks/src/common/otel.rs:71` — OTel span builder使用调用方提供的本地 `trace_id`/`parent_span_id`，没有 upstream TRACEPARENT 解析入口。
  - `kimi/constitution/20-mcp-skill-subagent.md:311` — Kimi 全栈未集成 OTel/traceparent 相关 SDK/字段。
- **Replay/source 证据**:
  - `kimi/constitution/20-mcp-skill-subagent.md:313` — `wire.jsonl` metadata 无 trace propagation 字段。
  - `kimi/kimihooks/tests/replay_fixtures.rs:59` — replay 从 wire fixture 生成本地 session trace，未消费外部上游 context。
- **数据源缺失根因**: Kimi CLI 的 hook/wire 协议不暴露上游 W3C context，且没有 HTTP/SDK propagation 边界可接入；当前无法区分“无上游调用”和“上游 context 未记录”。若未来 hook payload 增加有效 `TRACEPARENT`，应在 prompt/turn 边界显式捕获并让 replay 使用记录值。
