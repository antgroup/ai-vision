# D4 Cancel / Retry 错误恢复识别 {#d4}

- **评分**: 🟡
- **结论**: 原生 `MessageAbortedError` 结束当前已观测 Generation，标记 ERROR 和 `finish_reasons=["error"]`，只产生一次请求事件/计数。官方宿主可能先发 `session.error`、`session.idle` 再发最终 assistant 更新；插件在真实中断事件边界结束请求，重复 idle 不重复产生 `session_end`。缺失 usage 保持未知，不用宿主零值补齐。
- **API 错误**: `APIError` / `ProviderAuthError` 保留独立 CLIENT diagnostic；已存在 Generation 时不增加同一请求的计数。同 Turn 的前次失败没有语义输出时，下一 observed attempt 可复用原 input 快照；`isRetryable` 仅表示资格，不证明实际重试。
- **代码引证**:
  - `opencode/observ-opencode/src/hooks/provider-usage.ts:39-74`：原生中断终态、单次事件和指标。
  - `opencode/observ-opencode/src/hooks/index.ts:597-706`：独立 API diagnostic、已有 generation 的请求计数去重及 MessageAbortedError 处理。
  - `opencode/observ-opencode/src/hooks/provider-wire.ts:103-145`：沿用原 fetch / AbortSignal，解析真实响应中的 usage；取消不制造响应或 token。
- **Replay/source 证据**:
  - [`test-llm-usage-terminal.ts`](../observ-opencode/scripts/test-llm-usage-terminal.ts) / [`test-provider-wire-usage.ts`](../observ-opencode/scripts/test-provider-wire-usage.ts) 覆盖取消事件顺序、重复回调、AbortSignal 和 unknown/zero 负例。
  - 本地正式 1.18.34 CLI 的 native `cancel` fake-provider 场景验证实际中断、请求 ledger 与三信号 source；不将此单场景扩大为全部 retry / timeout 语义通过。
- **边界**: 仍不生成无法从宿主证明的 retry 序号/延迟、timeout 或 rate-limit 归因。自动传输层重试与原生 cancellation 的完整平台验收应以实际请求 ledger、三种 OTLP 信号及平台 readback 为准；hook 单元测试不能替代这些证据。历史 API 错误 replay 也不证明当前宿主全矩阵通过。
