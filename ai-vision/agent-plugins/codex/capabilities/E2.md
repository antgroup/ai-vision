# E2 上游调用 TRACEPARENT 串联

- **评分**: ✅
- **结论**: Codex 在 Turn seed 和实时 ToolContext 两条路径严格消费有效 `TRACEPARENT`。当前 Turn 复用上游 trace ID、root 使用上游 parent span；下游 Bash/Tool 获得以当前具体调用 span 为 parent 的新 `TRACEPARENT`。状态快照使异步 worker/finalizer 不依赖后续变化的全局环境。
- **代码证据**:
  - `agentic-otel-common/src/lib.rs:103` — 读取并解析 W3C `TRACEPARENT` 环境变量。
  - `codex/cdxhooks/src/common/turn_seed.rs:22` — prompt seed 从有效上游 traceparent 选取 trace ID。
  - `codex/cdxhooks/src/hooks/tool_context.rs:60` — PreToolUse 捕获 upstream traceparent/parent span，并保存到 realtime context。
  - `codex/cdxhooks/src/hooks/langfuse/langfuse_handler.rs:976` — finalizer 选择持久化上游 trace context，必要时才使用显式环境 fallback。
  - `codex/cdxhooks/src/common/otel.rs:2148` — `TurnReplayOpts` 将 trace ID、root parent span 和 SOFA context 传入共同 Turn 构造器。
- **Replay/source 证据**:
  - `codex/cdxhooks/tests/async_parent_integration.rs:848` — 固定 `TRACEPARENT` 驱动 prompt seed 与 PreToolUse 控制响应。
  - `codex/cdxhooks/tests/async_parent_integration.rs:895` — 断言下游命令的 `TRACEPARENT` 使用相同 trace ID 和当前 Tool span 派生的 parent。
  - `codex/cdxhooks/src/common/otel.rs:4360` — 固定 `TurnReplayOpts` 的 trace/parent 端到端构造测试。
  - `codex/cdxhooks/src/hooks/langfuse/realtime.rs:531` — realtime Tool payload 保留既定 trace/root parent topology。
- **边界**: Codex 的离线 replay 只有在显式提供 `TurnReplayOpts`/持久化 context 时才能复原 upstream parent；不能把 replay 进程当前环境中的 `TRACEPARENT` 当作历史输入。SOFA headers 作为独立字段处理。
