# E1 Git 仓库信息识别

- **评分**: 🟡
- **结论**: OpenCode 生产插件只在 host 明确声明 `project.vcs=git` 且提供 worktree 时探测仓库；两个 Git 命令并行执行、带超时和输出上限，非 Git/命令失败只返回部分或空属性。结果在 telemetry provider 初始化前并入 Resource，显式配置按 key 优先。功能已有源码、版本化脚本和生产入口 E2E 证据，但当前缺含自动探测结果的可复现 replay；revision 也未采集。
- **代码证据**:
  - `opencode/observ-opencode/src/vcs.ts:26` — Git 命令 runner 设置 `timeoutMs`、`maxBufferBytes`、kill signal，并把失败转成 undefined。
  - `opencode/observ-opencode/src/vcs.ts:59` — 仅接受 `project.vcs === 'git'` 的 worktree，分别获取 remote 与 branch，独立允许缺失。
  - `opencode/observ-opencode/src/index.ts:158` — telemetry 初始化前解析 VCS Resource，并保留配置值优先级。
- **Replay/source 证据**:
  - `opencode/observ-opencode/scripts/test-vcs-resource.ts:28,125-145` — 并发探测、单命令失败、detached HEAD、空值和超时场景测试。
  - `opencode/observ-opencode/scripts/test-vcs-production-entry.ts:25,80-89` — 临时 Git worktree + origin + production plugin OTLP request 验证 remote/branch Resource。
  - `opencode/observ-opencode/README.md:67` — 生产探测边界、失败降级、配置优先级和 detached HEAD 契约；同 README 明确 replay/report 不探测当前 cwd。
- **边界**: 当前上报 `vcs.repository.url.full` 与 `vcs.ref.head.name`，不采集 `vcs.ref.head.revision`。没有 project Git 标记或 worktree 时，即使进程目录位于父仓库也不探测，避免错误归属；revision 作为 E1 可选增强项。
