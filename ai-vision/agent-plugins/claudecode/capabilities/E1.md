# E1 Git 仓库信息识别

- **评分**: 🟡
- **结论**: Claude Code 在 `UserPromptSubmit` 的可信 `cwd` 上采集 session-scoped Git remote 与当前 branch，按 session/cwd 隔离保存；实时 Stop、realtime generation 和子 agent 消费该快照并注入 OTLP Resource。Git 探测有超时，非 Git/缺字段 fail-open。生产代码和隔离测试已证明 remote/branch 采集，但当前没有含 VCS Resource 的可复现 replay；revision 也不是当前主 Resource 快照字段。
- **代码证据**:
  - `claudecode/cchooks/src/common/git_state.rs:20` — `git_remote_url` 从 bounded `git remote -v` 选择远端，`git_branch` 读取 `rev-parse --abbrev-ref HEAD`，统一经过有界命令执行。
  - `claudecode/cchooks/src/hooks/resource_context.rs:23` — 仅响应 `UserPromptSubmit`，从 payload 读取 `session_id`/`cwd`，复用同 cwd 的 remote、每轮刷新 branch，并把快照写入 session state。
  - `claudecode/cchooks/src/common/otel.rs:2953` — `inject_vcs_resource_attrs` 将非空 `vcs.repository.url.full` / `vcs.ref.head.name` 幂等注入每个 OTLP Resource。
  - `claudecode/cchooks/src/main.rs:760` — ResourceContextHandler 在 realtime/tool consumers 前注册，确保仓库快照先被采集。
- **Replay/source 证据**:
  - `claudecode/cchooks/tests/state_integration.rs:167` — 两个 session/cwd 的 VCS snapshot 相互隔离，并验证 remote、branch 不串会话。
  - `claudecode/cchooks/src/hooks/resource_context.rs:307` — Git 探测/状态故障为 fail-open，不因锁争用或缺字段阻断 hook。
  - 本机 host transcript（未纳入仓库）含可信 `cwd` 字段；但当前仓库未保留对应含仓库 Resource 的版本化 replay，不能以本机 runtime artifact 作为额外 Golden 证明。
- **边界**: 只承诺 remote URL 与 HEAD 引用名；detached HEAD、无 remote、非 Git 目录或 Git 超时保持缺失。`vcs.ref.head.revision` 当前未由该生产 Resource snapshot 采集。实时与 replay 的语义可共享，但 offline replay 不应访问 replay 进程当前工作目录。
