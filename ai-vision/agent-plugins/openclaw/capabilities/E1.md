# E1 Git 仓库信息识别

- **评分**: ⚪
- **结论**: OpenClaw 在本轮能力边界中属于常驻 gateway/service，负责跨会话接收消息和运行 agent，而不是由一个稳定用户 worktree 驱动的短生命周期仓库采集器；本轮不要求它为每个会话推断 Git 仓库，因此标记为不适用，而不是未实现。
- **代码证据**:
  - `openclaw/observ-openclaw/README.md:5,17-31` — 插件面向 gateway/session lifecycle，记录 gateway、session、message、agent 与工具生命周期。
  - `openclaw/observ-openclaw/src/hooks/session-lifecycle.ts:26,79-118` — session lifecycle 以 `sessionKey`/`sessionId` 管理长期进程中的会话状态，而不是以用户 worktree 作为仓库身份。
  - `openclaw/observ-openclaw/src/telemetry.ts:80` — Resource builder 的输入是服务/agent identity 与显式配置，没有稳定 host worktree contract。
- **Replay/source 证据**:
  - `openclaw/CAPABILITIES.md:13` — 当前 OpenClaw 能力评估以 gateway hooks、session/agent/LLM/tool lifecycle 为对象，没有 Git worktree source；这与“常驻程序不要求 E1”的产品边界一致。
  - `openclaw/openclaw-replay/README.md:1` — replay 是回放 callback transcript 的独立开发者产品，不从 replay 进程当前目录推断仓库。
- **数据源缺失根因**: OpenClaw plugin contract 没有本轮可依赖的稳定 project/worktree/cwd 归属字段；常驻 gateway 可能服务多个会话，进程 cwd 不能安全代表任一会话仓库。若未来 host 暴露 session-scoped worktree provenance，应重新评估 E1；在此之前不得用 `process.cwd()` 猜测。
