# E1 Git 仓库信息识别

- **评分**: 🟡
- **结论**: Codex 在 `UserPromptSubmit` 根据 payload `cwd` 做一次有界 Git repository snapshot，并按 session state 保存；后续 realtime、Stop/finalizer、tool/batch 和 child-session isolation 使用该 session-owned provenance 注入 Resource。生产代码、隔离和清理测试已覆盖 remote/branch，但当前没有含 VCS Resource 的可复现 replay；revision 也未采集。
- **代码证据**:
  - `codex/cdxhooks/src/common/git_state.rs:64` — `collect_git_repository` 并行语义上独立地处理 `git remote -v` 与 `git rev-parse --abbrev-ref HEAD`，区分 captured、definitive absence 与 unavailable。
  - `codex/cdxhooks/src/hooks/resource_context.rs:23` — `UserPromptSubmit` 读取 `cwd`，调用 bounded collector，并把 snapshot 写入 session-owned state；非仓库时清理旧 VCS，暂时不可用时避免错误覆盖。
  - `codex/cdxhooks/src/common/otel.rs:3586` — `inject_vcs_resource_attrs` 幂等 upsert `vcs.repository.url.full` / `vcs.ref.head.name` 到 OTLP Resource。
  - `codex/cdxhooks/src/common/otel.rs:3680` — `isolate_session_vcs_resource` 防止父/子 session 的仓库 provenance 泄漏，并允许空值移除继承字段。
- **Replay/source 证据**:
  - `codex/cdxhooks/tests/resource_context_integration.rs:68` — 两个并发 session 的 remote/branch 隔离、branch refresh，以及切换到非仓库时清除陈旧 snapshot。
  - `codex/cdxhooks/src/common/otel.rs:7039` — Resource 注入幂等性、重复键去重、child-session repository isolation 与 empty cleanup 测试。
  - `codex/cdxhooks/tests/resource_context_architecture.rs:92` — Stop/worker 无 Git discovery fallback，只有 ResourceContext 负责写入仓库状态。
- **边界**: 当前主路径提供 remote URL 与 HEAD 引用名，不提供 `vcs.ref.head.revision`；replay 若没有随输入保存的 session snapshot，不得自行读取 replay 进程 cwd。远端选择遵循代码中的 remote ranking，不将任意 parent repository 猜作当前 worktree。
