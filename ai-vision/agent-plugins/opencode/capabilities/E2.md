# E2 上游调用 TRACEPARENT 串联

- **评分**: ⚪
- **结论**: OpenCode 当前 hook/plugin contract 没有可证实的 W3C `TRACEPARENT` 输入或 session-scoped upstream parent context。OpenCode 自身 hooks 使用 OTel `context.active()` 连接插件内部 span，但不能把插件内部 parent 误称为外部上游调用串联，因此本轮评为 ⚪。
- **代码证据**:
  - `opencode/observ-opencode/src/hooks/index.ts:157` — `createHooks` 包装 tracer 并使用当前 OTel context，属于插件内部上下文。
  - `opencode/observ-opencode/src/hooks/session.ts:175` — lifecycle event 关联 active/retained span，不读取 `TRACEPARENT`。
  - `opencode/observ-opencode/src/vcs.ts:1` — 当前 host context 只扩展 Git Resource discovery，没有 W3C propagation source。
- **Replay/source 证据**:
  - `opencode/opencode-replay/src/raw-envelope.ts:1` — replay envelope 记录 callback/session correlation，但没有版本化 upstream traceparent 字段。
  - `opencode/opencode-replay/src/report.ts:55` — replay/report 仅消费既有 span parent IDs，不从当前进程环境构造历史 upstream parent。
- **数据源缺失根因**: OpenCode SDK/hook 输入未暴露外部 W3C trace context；`context.active()` 只表示当前 OTel provider 已有的内部 context。若未来 host 提供 request headers/diagnostic trace context，应增加显式 capture 与 replay fixture 后重新评估。
