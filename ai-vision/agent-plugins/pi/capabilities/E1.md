# E1 Git 仓库信息识别

- **评分**: ❌
- **结论**: Pi runtime/plugin context 已提供 `cwd` 和 project trust 信息，但当前 SemanticEngine、Resource builder 与 replay input 没有采集或上报 Git remote、HEAD branch/revision；这是数据源存在而实现未采集的工程缺口。
- **代码证据**:
  - `pi/observ-pi/src/index.ts:225` — production initialization 明确接收 `ctx.cwd` 并据此加载 project configuration。
  - `pi/observ-pi/src/config.ts:178` — config path resolution 以可信 `cwd` 区分 global/project context。
  - `pi/observ-pi/src/semantic.ts:362` — 当前公共 span context 只写 session/chat/runtime identity；没有 `vcs.*` 采集或 Resource 注入。
  - `pi/observ-pi/src/telemetry.ts:80` — Resource 直接来自 configured attributes，未包含 Git discovery。
- **Replay/source 证据**:
  - `pi/pireplay/src/index.ts:35` — replay 记录 hook context/correlation，但没有 VCS source 字段或 Git snapshot。
  - `docs/data-use/pi/traces.md:136` — 当前 trace 明确不报告 VCS URL/ref/revision；这证明现状，不是数据源不可得结论。
- **缺失原因**: Pi 的 `ctx.cwd` 可作为可信 worktree 候选，且 production/replay 都有 session context；缺少的是 Git collector、session-scoped snapshot、Resource 合并及显式 replay source。补法应使用有界、失败安全的 Git probe，并避免 replay 读取自身当前目录来改变结果。
