# D4 Cancel / Retry 错误恢复识别

- **评分**：🟡
- **结论**：Pi 能把 provider retry/supersede 和 session shutdown 转为 cancelled error，并对同一请求保留 retry input snapshot；但没有用户主动 interrupt 的正式 Golden，也没有独立 retry attempt/delay 语义字段。
- **代码证据**：
  - `pi/observ-pi/src/semantic.ts:411-447` — 新 provider request 关闭旧 generation 为 `cancelled`，并标记 usage missing。
  - `pi/observ-pi/src/semantic.ts:563-588` — shutdown 对 pending LLM/tool/compaction/Turn 统一以 cancelled 终态关闭。
  - `pi/observ-pi/src/input-materializer.ts:292-319` — equal retry 复用完整当前 snapshot，append 只发新增 suffix。
- **Replay/source 证据**：
  - `pi/observ-pi/test/core.test.ts:119-152,224-260` — retry supersede、shutdown cancellation 和 observation order 回归。
  - `pi/GOLDEN_BASELINE.md:28-32` — Golden superloop 有 rate-limit retry 清理/重试，但没有 user-interrupt cancel 场景。
- **缺口**：补 retry attempt/delay、用户取消 transcript，以及 realtime/replay 对 cancel 语义的一致性验证。
