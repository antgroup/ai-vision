## Kimi-CLI 数据生态总览

`kimi-cli` 与 `claudecode` 同属“外部二进制 hooks”运行时模型，但数据来源更为多源：

| 数据通道 | 来源 | 用途 |
|---|---|---|
| Hooks stdin payload | `src/kimi_cli/hooks/events.py` 13 个事件 builder | turn / tool / compaction / subagent 边界与精确字段 |
| `wire.jsonl` | `~/.kimi/sessions/<md5(cwd)>/<session_id>/wire.jsonl` | UI 事件流：`TurnBegin/End`、`StepBegin`、`StatusUpdate(token_usage)`、`ContentPart`、`ToolCall`、`SubagentEvent` |
| `context.jsonl` | 同目录 | kosong messages 完整对话历史，含 system / user / assistant / tool_calls / tool_results |
| Hook 镜像事件 | `wire.jsonl` 中的 `HookTriggered` / `HookResolved` | hooks 触发自带 wire 镜像，可用于 cross-check |

宪章证据通常从“hooks 字段优先 → wire.jsonl 兜底 → context.jsonl 复核”三层来源依次回退。

## 总览矩阵

| 条款 | 结论 | 主要数据来源 | 可靠性 | 实现代价 | 架构影响 | 建议 |
|---|---|---|---|---|---|---|
| C1 Turn / Root Span | 支持 | `UserPromptSubmit` + `Stop` / `StopFailure` hooks + wire `TurnBegin` / `TurnEnd` | 原生可得 | 低 | 低 | 必须 |
| C2 LLM 请求与耗时 | 部分支持 | wire `StepBegin` + `StatusUpdate.token_usage` + `context.jsonl` assistant message | 弱时间边界 + 强消息内容 | 中 | 低 | 必须 |
| C3 Tool 调用与耗时 | 支持 | `PreToolUse` + `PostToolUse` / `PostToolUseFailure` hooks（含 `tool_call_id`） | 原生可得 | 低 | 低 | 必须 |
| C4 MCP 工具 | 支持 | `tool_name` 命名空间前缀（fastmcp 标准） | 原生可得 | 低 | 低 | 必须 |
| C5 Skill 工具 | 部分支持 | `/skill:` `/flow:` 注册前缀 + `UserPromptSubmit.prompt` 识别 | 原生可得 | 低 | 低 | 推荐 |
| C6 Subagent | 支持 | `SubagentStart` / `SubagentStop` hooks + wire `SubagentEvent` 嵌套 | 原生可得 | 低 | 低 | 必须 |
| C7 跨 Trace 关联 | 暂不支持 | 每个 turn 独立 trace_id，与 `claudecode` 一致 | 不适用 | 高 | 高 | 放弃 |
| C8 Compaction | 支持 | `PreCompact.token_count` + `PostCompact.estimated_token_count` 原生 | 原生可得 | 低 | 低 | 必须 |
| C9 Messages | 支持 | `context.jsonl` 直接读取 kosong messages | 原生可得 | 低 | 低 | 必须 |
| C10 增量 Input | 支持 | replay 阶段从 `context.jsonl` 计算 step 间差异 | 推导 | 中 | 低 | 必须 |
| C11 Token | 支持 | wire `StatusUpdate.token_usage` (`kosong.TokenUsage`) | 原生可得 | 低 | 低 | 必须 |
| C12 System Instructions | 暂不支持 | 无原生 hook；`context.jsonl` 含 system message 但路径未稳定 | 不适用 | 高 | 中 | 放弃 |
| C13 并发工具 | 部分支持 | `toolset.py:492` `asyncio.gather`；同 turn 内多 `PreToolUse` 时间窗判定 | 推导 | 中 | 低 | 推荐 |
| C14 Cancel/Retry | 部分支持 | `StopFailure(error_type, error_message)` + wire `StepInterrupted` 原生 | 原生可得 + 局部缺失 | 低 | 低 | 推荐 |
| C15 截断与缺失 | 推荐 | 实现层 `truncate_value()` + `agentic.tool.input.missing` 标记 | 实现可得 | 低 | 低 | 推荐 |

## 与 ClaudeCode 的对比

| 条款 | kimi-cli | claudecode | 差异说明 |
|---|---|---|---|
| C1 | 支持 | 部分支持 | 时间边界更精确（hook 自带 turn boundary） |
| C3 | 支持 | 部分支持 | 错误事件原生独立（`PostToolUseFailure`），无需字段嗅探 |
| C6 | 支持 | 部分支持 | `SubagentStart/Stop` 原生事件，`SubagentEvent` 嵌套子流 |
| C8 | 支持 | 支持 | `PreCompact` / `PostCompact` 双事件 + token 原生 |
| C11 | 支持 | 部分支持 | `kosong.TokenUsage` 经 `StatusUpdate` 原生流出 |
| C14 | 部分支持 | 部分支持 | `StopFailure` 原生提供 `error_type` / `error_message` |
| 其余 | 与 claudecode 等价或更弱 | — | C2 弱于 cc（无原生 LLM 边界 hook） |
