# C7 LLM Token usage 识别 {#c7}

- **评分**：🟡
- **现行能力**：用量属于每个 LLM generation；Turn 根不再写聚合 token。终态的零用量和未知用量均产生一次请求事件/计数，重复 callback 和同请求的 `session.error` diagnostic 不重复累计。
- **OpenAI-compatible provider**：官方 `config` hook 包装已配置 provider 的 `options.fetch`，`chat.headers` 提供真实 session / agent / message 关联。它观察实际响应中的 usage，再交回对应主 generation；不使用宿主将缺失数据归一后的零值证明 provider 报告零。实际 `title` / `summary` / `compaction` 辅助调用是携带原 session 和 agent 名的独立 generation，参与请求和 token 指标；由官方源 message ID 派生 `aux:<agent>:<message id>`，并使用 boolean `agentic.llm.auxiliary=true`。没有猜测 Turn 父节点或编号；未知 agent 和未关联的主调用不能使用该例外。
- **Token 口径**：响应的 input/output 为 inclusive 值，保留实际 total、cache read/write 和 reasoning。尤其 OpenCode 可能将 output 减去 reasoning，或丢失 cache write；已捕获的 provider 事实优先于这些宿主归一结果。未知 input/output 写对应的 `agentic.usage.input_tokens.missing` / `agentic.usage.output_tokens.missing=true`；兼容所需的数值占位零不代表真实零。未知 total 和可选明细直接省略；只有 input 和 output 都已知时才可派生总量。fresh-input token counter 和 cache counters 分开，不能直接将 fresh counter 当作 inclusive 供应商账。没有 wire 数据时，按宿主的 visible-output / reasoning 分桶合并 canonical output，span、请求事件与 output counter 使用同一口径；这不证明宿主本身提供了完整供应商账。
- **隐私和传输**：仅增量解析有界 usage 行，原字节直接转发，不 tee/缓存完整回复、不记录 headers 或 key；保留原 fetch、abort 和取消行为。辅助 generation 的 IO 固定为 `[REDACTED]`，该路径只证明调用身份与 usage。

- **边界**：wire adapter 仅覆盖明确配置的 `@ai-sdk/openai-compatible` Chat Completions provider。Anthropic、Responses API、experimental native LLM adapter 和别的宿主版本仍需要各自验证。过长/损坏响应中的 usage 留为未知；不回填估算值。自动重试等多个 physical HTTP attempt 共享同一 AssistantMessage 的场景仍需单独对账。
