# E3 非真实用户 / 外部触发归因识别

- **评分**：🟡
- **现行能力**：外部调用者可通过 `AIVISION_META_TRIGGER`，或 `otelExporter.resourceAttributes["ant.meta.trigger"]`，明确提供 process/task 归因。最终 Resource 在 traces、metrics、events/logs 间共用；环境变量覆盖各 Resource 配置层，支持 `automation` / `interactive` / `unknown`，非法或显式空值归为 `unknown`。两种入口都未配置时保留空字符串。
- **代码证据**:
  - `opencode/observ-opencode/src/config.ts:362-382`：合并 Resource 配置，专用环境变量覆盖已配置归因。
  - `opencode/observ-opencode/src/telemetry.ts:51-95`：最终 Resource 保留归因；`opencode/observ-opencode/src/telemetry.ts:118-122`：三个信号共用同一个 Resource。
  - `shared/meta-trigger.mjs:12-27`：合法值、显式非法值和缺失默认值的规范化。该能力已在现有代码中实现，不是本轮新增修复。
- **Replay/source 证据**:
  - [`test-config-priority.ts`](../observ-opencode/scripts/test-config-priority.ts) 覆盖配置优先级；[`test-production-boundary.ts`](../observ-opencode/scripts/test-production-boundary.ts) 对三个真实本地 OTLP 路径核对 Resource-only 属性。
- **需求边界**：外部触发归因要求 Resource 归因与宿主观察到的 Turn trigger；当前覆盖 Resource 归因，因此保持 🟡。
- **边界**：这是调用者显式提供的进程归因，不是从 prompt/session 文本或 Git 环境推测的真实用户身份。它不会生成 `agentic.turn.trigger`，也不会传播到 generation/tool 属性。本轮 native 读取场景未单独验收自动化 trigger 的平台/UI 表示。
