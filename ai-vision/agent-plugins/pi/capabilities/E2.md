# E2 上游调用 TRACEPARENT 串联

- **评分**: ⚪
- **结论**: Pi 当前 hook contract 只提供 session manager、cwd 和 Pi lifecycle payload，没有可证实的外部 W3C `TRACEPARENT` source。`observ-pi` 能沿用当前 OTel context，且可为派生 Skill 创建 link，但没有上游调用的 traceparent 输入，不能声称完成 E2。
- **代码证据**:
  - `pi/observ-pi/src/index.ts:225` — production plugin 从 ExtensionContext 初始化 session/project 状态，没有上游 traceparent 字段。
  - `pi/observ-pi/src/telemetry.ts:171` — 当前实现解析 observation 内部 parent/link keys，属于插件内部语义，不是外部 TRACEPARENT propagation。
  - `pi/observ-pi/src/types.ts:76` — canonical observation 的 parent/link 字段服务于本地 span 组装，没有 W3C header/context source。
- **Replay/source 证据**:
  - `pi/pireplay/src/raw-envelope.ts:1` — replay envelope 的字段 allowlist/correlation 没有 upstream TRACEPARENT。
  - `pi/observ-pi/test/telemetry-lifecycle.test.ts:145` — 测试的 upstream parent 是直接注入 OTel Context 的单元场景，并非 Pi host 暴露的 TRACEPARENT source，因此不能作为生产 E2E 证据。
- **数据源缺失根因**: Pi host API 当前不暴露外部调用方的 W3C header 或 session-scoped parent context；不能从 `context.active()` 或本地 span 反推调用方。未来若 host 提供该 source，应将其纳入 raw envelope 并验证 replay 不读取当前环境。
